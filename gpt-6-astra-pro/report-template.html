Interpretation & limitations

  1. Timing units are an explicit assumption. The JSON has no unit dictionary. Elapsed and CPU times are displayed as seconds; cluster CPU ÷ CPU-hours is consistent with 3,600 seconds/hour. Memory-time hours use the source’s unspecified memory unit.
  2. Reported is not always canonical. Charts default to the source’s time field. Canonical totals use canonical without substituting missing values. TPC-DS tuned Rust at SF 1,000 differs between these fields; some Gluten and Spark totals have no canonical value.
  3. Matched ratios and source flags are not reinterpreted. The definitions of matched, B, P, “pass,” “gap,” and the Q39 ULP policy are not supplied. No correctness conclusion is inferred from them.
  4. Coverage matters. Cluster SF 10,000 aggregates contain 94 paired queries. Q23, Q39, Q67, Q78, and Q95 are unpaired or missing and remain visible in the explorer. Query sums can differ slightly from supplied totals due to source precision; aggregate charts use the supplied totals.
  5. Totals are not averages of ratios. Combined single-node totals add four scales and are dominated by the largest workload. Percent differences in this report are computed from totals, not averaged query speedups.
  6. Experimental details are incomplete. Run counts, dispersion, warm-up/cache policy, storage, engine settings, cost, and detailed validation procedures are not included. The cluster benchmark name is not explicit in the JSON. These are not official TPC benchmark results.
